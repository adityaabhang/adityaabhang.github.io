Multi-Robot Warehouse Kitting & Fulfillment

Simulation-based design of an autonomous multi-robot system for warehouse coordination and material handling

📅 Spring 2026  •  🏫 Purdue University  •  🤖 IE 574 — Industrial Robotics  •  👥 Group 7 (6 members)

CoppeliaSim Lua Scripting Multi-Robot Coordination Signal-Based Control System Architecture Industrial Control Material Handling Simulation & Validation
How it works — the big picture

Five robots and one coordinator turn a kit list into a packed tray, with no human in the loop.

Order inA kit list says which parts each tray needs.
Coordinator assignsA PLC-style controller hands each step to the right robot.
Robots signalEach robot reports request, busy, or done so work never overlaps.
Pick, sort & carryThe UR10 sorts by colour; mobile robots move bins down the line.
Kit outThe tray is counted as fulfilled only when it leaves fully loaded.

What Did I Do?

I was responsible for the Pick-and-Place Robot (UR10) workflow — the upstream station that inspects incoming parts via color vision and sorts them into the correct producer bins. This involved designing the full state machine for the robot: detecting part color using a CoppeliaSim vision sensor, computing bin placement coordinates, executing the pick-and-place motion sequence, and signaling completion back to the central coordinator.

Beyond my individual robot, I contributed to system-level architecture decisions: the coordinator design, the request-busy-done signal protocol, and the order tracking logic that ensures fulfillment counts are only incremented at the final tray unloading stage — not at intermediate transport steps.

Problem Statement

Modern warehouse kitting and fulfillment systems face increasing pressure to respond to changing demand, shorter delivery expectations, and stricter accuracy requirements. Traditional kitting processes often rely on fixed workflows, manual handling, or isolated automation that becomes inefficient when demand shifts suddenly or disruptions occur.

This project addresses a clear gap: the need for a validated system-level framework that links upstream part generation, intermediate pick-and-place actions, bin transport, final tray loading, and fault recovery within one integrated operating environment. Rather than evaluating each subsystem in isolation, the project models the complete end-to-end workflow from order entry through delivery preparation.

System Architecture

The simulated system uses a coordinator-based control structure that resembles real PLC-based industrial systems. Five robotic subsystems operate under a single supervisory coordinator:

  • Parts Producer — Demand-driven part generation with spawn area validation
  • Pick-and-Place Robot (UR10) — Vision-based color inspection and sorting into producer bins
  • Mobile Robot 1 (PioneerP3DX + UR5) — Upstream bin transport from producer to kitting station
  • Mobile Robot 2 (KUKA youBot) — Downstream bin transport from kitting to delivery preparation
  • Cobot (UR10) — Final part unloading into shipping trays and empty bin removal

The central Coordinator manages system state, assigns work, monitors robot status, and ensures reliable handoffs between stations. No robot communicates directly with another — all sequencing flows through the coordinator.

Control Architecture

System integration relies on a disciplined request-busy-done signal protocol:

  • Coordinator issues req_* request signals to a robot with task data
  • Robot sets *_busy = 1 when task is accepted and actively executing
  • Robot sets *_done = 1 upon task completion

This three-phase handshake prevents overlapping claims on work items and provides reliable feedback. Each robot implements a local state machine that responds only to coordinator-issued requests, reducing local autonomy in favor of traceability.

Order Tracking & Completion Logic

Order progress is managed exclusively by the supervisory layer. Original order quantities are preserved while active remaining quantities are decremented during fulfillment. Completion is defined only at the point of final tray unloading — not at earlier transport stages — preventing false completion states where parts have been produced or moved but not yet delivered.

Key Contributions

  • Centralized supervisory control: Demonstrated how a PLC-style coordinator can effectively manage multi-stage robotic workflows without direct robot-to-robot communication
  • Demand-driven production: Showed the importance of tying upstream part generation to actual order signals rather than uncontrolled random spawning
  • Signal-based coordination: Validated the request-busy-done handshake pattern for reliable inter-station task sequencing
  • System-level integration: Exposed integration complexity across six subsystems (producer, conveyor, camera, pick-and-place, mobile robots, cobot)
  • Resilience testing: Included disruption scenarios (pickup failures, material-flow interruptions, transfer delays) to evaluate safe recovery behavior

Design Highlights

Coordinator-Based Architecture

The architecture separates system-level decision-making from robot-level execution. The coordinator maintains shared system state and tracks bin status throughout the workflow. This structure improves traceability, simplifies debugging, and ensures consistency across the full process by giving one authoritative source of truth for work assignments and robot availability.

Demand-Driven Part Generation

The Parts Producer generates parts only when active orders exist and the spawn area is confirmed clear. This avoids inventory buildup and keeps the simulation aligned with the downstream fulfillment rate. Simpler part geometries (cuboids, cylinders) were used instead of complex polygonal shapes after finding that intricate geometry caused unstable physics behavior in CoppeliaSim.

Mobile Robot 2 Grasping

Downstream transport with the KUKA youBot required precise coordination between the mobile base, arm, gripper, and station geometry. Tuning involved iterating on gripper opening range, approach poses, stopping distance, and staging height until reliable grasps were achieved. This subsystem represented the highest implementation effort of the project.

Performance Metrics

System behavior was assessed using practical production measures:

  • Throughput: Number of fulfilled parts and completed kits per simulation run
  • Cycle time: Elapsed time from order submission to final tray unloading
  • Utilization: Proportion of time each robot spends actively executing tasks
  • Availability: Proportion of time the system remains able to execute required tasks
  • Mean time to recovery: Average time to restore workflow after a fault condition

Key Findings

  • The supervisory control concept provided a workable method for coordinating the full order-fulfillment process in a way that mirrors real industrial PLC-based systems
  • Demand-driven production proved more realistic and better aligned with the fulfillment sequence than uncontrolled random spawning
  • System success depends on coordinated timing and signal discipline across all interacting subsystems, not isolated task execution
  • The request-busy-done structure is sufficient for reliable inter-station handoffs without direct robot-to-robot communication
  • Downstream transport (Mobile Robot 2) requires precise interaction between mobile base, arm, gripper, and station geometry — repeatability depends on well-defined physical interfaces and disciplined operating conditions
  • Centralized order tracking improved consistency and preserved system state integrity across the full workflow

Implementation Insights

  • Spawn area validation before part generation was required to prevent collision at the producer station
  • Complex polygonal part shapes caused unstable physics; simpler cuboid and cylinder geometries improved simulation reliability
  • Mobile Robot 2 grasping required iterative tuning of gripper range, approach vectors, stopping distance, and staging height
  • The hardest implementation work was not high-level sequencing but matching robot motion, object geometry, and station interfaces precisely enough to achieve repeatable execution
  • Signal naming conventions required strict team-wide agreement — even minor mismatches in naming or timing broke inter-station handoffs

Scope & Assumptions

To keep the study focused on system coordination, several simplifying assumptions were used:

  • Producer bins have a maximum capacity of one part at a time
  • Single active system-level controller (not distributed negotiation)
  • Robots execute only coordinator-issued requests (reduced local autonomy for traceability)
  • Order completion is defined at final tray unloading, not at earlier stages
  • Empty bins logically reset to producer location rather than being physically returned

These assumptions are appropriate for a proof-of-concept study but define the limits of generalization to real-world deployment.
